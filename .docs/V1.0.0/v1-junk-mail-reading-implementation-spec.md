# V1 实现 Spec：垃圾邮件阅读与文件夹设置

状态：待实施。业务以[设计文档](./v1-junk-mail-reading-design.md)为准。交付包括文件夹角色覆盖、会话列表可见性、正文行为和单封移动。**不做**发件人封禁、自动识别追踪、图片授权、文件夹手动同步、监听或拉取频率配置。

## S1. 文件夹设置与数据契约

- `SettingsPage.vue` 的账号文件夹行新增「设置」入口。弹窗显示当前文件夹名和单选项：自动识别 / 是垃圾文件夹 / 不是垃圾文件夹。打开时读取**已保存选项**，不是由生效角色反推；保存中防重复提交，失败保留弹窗与原已生效设置。同步开关不受影响。
- `mail_folder_sync_state` 保留现有 `role` / `role_source` 自动识别结果。新增可空 `junk_override`（NULL=自动，1=是，0=不是），通过 `(account_id, folder_id)` 保存。V1 按仓库约束直接调整初始化 schema；开发库需要新建时明确说明，不自动删除现有数据库。发现文件夹的 upsert 不写该覆盖列；同名但不同身份的新文件夹不继承旧设置。
- 生效规则：覆盖为 1 → `junk`；覆盖为 0 且自动角色为 `junk` → `custom`；其他情况保留自动角色。自动档直接恢复已有识别结果，不新增名称猜测。保留服务器角色及来源以区分默认垃圾夹和人为候选。生效规则要统一用于会话查询、消息 `folder_role` 投影和移动目标，不在前后端各写一套。
- 沿用现有 Sync Port 新增 `setFolderJunkOverride` → Tauri `set_folder_junk_override`；请求字段 `account_id`、`folder_id`、`junk_override: boolean | null`，响应返回更新后的文件夹状态（含覆盖值与生效角色）。补齐 Memory Adapter、DTO、命令注册和 `permissions/app-ipc.toml`。拒绝跨账号、不存在或已退役的文件夹。覆盖更新、必要投影更新及账号版本递增在同一事务；提交后通知。不要开启网络同步来使设置生效。

## S2. 会话列表、详情与正文

- 查 `repository/sessions.rs` 中当前排除 `junk` 的默认会话条件，以及 `domain/services/folder_role.rs` 的共享规则调用者。仅调整为满足**已同步垃圾邮件默认可见**；保留 Trash、Drafts、All 及现有删除/隐藏规则。不顺带改变全局未读计数策略；若同一谓词同时管理可见性和未读计数，只拆开这一处语义。
- 仅含垃圾邮件的会话能出现在默认列表并打开，有文本摘要；混合会话中每封按自己的生效角色显示「垃圾邮件」，不按整个 Session 一刀切。正文详情、列表摘要和卡片用同一个消息角色来源，不根据显示名称、发件人或 Message-ID 推断。
- `MailReadingPane.vue` 将当前消息生效角色传给 `MailBodyView.vue`。普通 HTML 删除逐封授权横幅与 toggling 状态，直接在隔离 iframe 内渲染，复用允许图片的净化路径；保留 sandbox、CSP、URL 策略和 `no-referrer`。不因此打开脚本、表单、直接导航或其他远程资源类型。
- 垃圾正文优先用已有纯文本内容，否则把 HTML 当字面文本。不得用 `v-html`、挂载 iframe、激活正文 URL 或产生图片等远程请求。正文准备/loading 时不得短暂落入普通渲染分支。切信或角色更新后，只有当前账号、会话与消息的有效响应才能更新详情，旧 HTML iframe 应卸载。
- 角色改变后通过现有变更事件和版本补偿更新列表、卡片以及当前打开的正文；不重拉正文、不新增轮询。仅更新账号导航但不更新打开详情，不算完成。

## S3. 单封邮件移动

1. 在阅读区右上角：普通邮件提供「标为垃圾邮件」，垃圾邮件提供「移出垃圾邮件」。本地发信记录、没有有效远端位置或已有冲突移动意图的消息不能提交。命令按账号与当前消息 ID 定位，不以 Session 为操作范围；沿用现有 Message Port、Tauri 命令注册与权限链。
2. **标为垃圾**：优先使用仍生效的、由协议确认的同账号标准垃圾夹；没有唯一标准目标时，只有唯一生效垃圾夹才可选。歧义、目标无效或找不到时提示去文件夹设置，不按名称随便挑。**移出**：仅使用同账号已确认且生效角色不是垃圾的收件箱；不记录原文件夹。同步开关不被操作修改。
3. 复用 `message_use_case.rs`、`repository/mutations.rs` 及底层 IMAP UID MOVE / Graph move 的现有位置检查、待处理意图与结果记录；扩展必要的动作区分，不把「标垃圾」冒充删除。核对账号、源位置修订和目标绑定；遇到绑定变化、目标退役或不支持安全移动时明确失败，不使用整箱 expunge 或静默退化为删除。移出后的新位置按普通同步入库，不按 Message-ID 重绑或合并旧实体。
4. 标记后可立即暂停该封的 HTML，失败后恢复普通展示并提示。移出在仅入队、处理中、失败或远端结果未知时仍为文本；确认后由新位置角色决定是否渲染。若新位置还没同步，刷新会话并等待，不解锁旧详情。提交成功但结果未确认时，不显示「已移出」。

## 实施顺序与验收

先交 S1（设置可保存、刷新不覆盖），再交 S2（列表与安全正文），最后交 S3（两协议移动）；每步保持可编译。不做通用配置表单或调度器。

| 验收项 | 必测结果 |
| --- | --- |
| 自动识别与三态覆盖 | IMAP `\\Junk` / Graph 标准垃圾夹在自动档被识别；手动否定及手动指定在重新发现、重启后仍有效；切回自动恢复协议结果，非垃圾角色不被覆盖为 `custom` |
| 默认列表与角色更新 | 仅含垃圾邮件的会话能打开；同会话普通/垃圾分开标注；覆盖变更对已有及新同步邮件一致，不改同步开关；迟到响应不让垃圾正文重新渲染 |
| 正文隔离 | 普通邮件允许的图片能直接显示，无授权提示；垃圾邮件有纯文本时显示纯文本，否则源码按文字显示。切换和设置变更后无正文 iframe、无远程请求；普通邮件原有隔离仍有效 |
| IMAP / Graph 单封移动 | 只影响选中邮件；校验标准目标、唯一手动目标和歧义；缺目标、无位置、远端失败、仅入队及结果未知时不误报、不解锁垃圾正文；成功后按新位置显示 |
| 桌面 IPC | 用 Tauri 实际调用保存设置及移动，确认命令已注册且允许；仅 TypeScript 检查不能覆盖 IPC 权限 |

验证建议：`cargo test --lib --offline`、`cargo test --test end_to_end_acceptance --offline`、`pnpm exec vue-tsc --noEmit`，另跑列表/正文的界面测试和可控协议移动测试。交付说明实跑命令、覆盖场景与未测边界。本文只定义实施规格，未改产品代码或执行验收。
