# V1 设计修复：发信记录留在会话，不做 Sent 目录

状态：**设计已自审，待确认实施**。本文承接[范围建议](./v1-send-state-and-sent-scope.md)。确认后，本文取代 [Task 14](./tasks/imap-smtp/14-sent-archive.md) 中 V1 客户端 Sent 归档要求；不改变发送队列和普通邮件同步的职责。

## 1. 产品行为

- **会话是发信入口，也是发信历史。** 点击发送后，原会话显示已入队的本地消息。重启再打开，仍可看到发给谁、发送内容及最后状态；只发过邮件、从未收到回信的会话也应能从默认会话列表打开。新入队、成功、失败、结果未知及取消移除，不需要切换会话才能看到。
- **服务端受理即「已发送」。** SMTP 最终接受响应或 Graph `202 Accepted` 足够；不等收件人收到，也不等 Sent 副本出现。
- **V1 不提供独立「已发送」目录，也不维护 Sent 副本。** 不显示归档策略、不补写、不对账、不提示「等待归档」。服务商自行保留的副本仍可按现有通用同步规则进入会话；没有副本不报错，也不影响本机查阅。Postlet 不承诺其他客户端可见，也不承诺清库或换设备后恢复仅存在本机的发信历史。

| 提交证据 | 会话状态 | 后续处理 |
| --- | --- | --- |
| 已入队 / 正在尝试 | 待发送 / 发送中 | 复用持久化队列 |
| 服务器明确接受 | 已发送 | 保存本地结果，不再发送 |
| 能确认未被接受 | 待重试或发送失败 | 临时错误沿用退避；永久错误提示原因，不自动重试 |
| 调用中断，无法确认是否接受 | 发送结果未知 | 不自动重发；用户可在会话主动再发，若提供快捷重发入口，须先提示可能重复 |

不新增云端发信查询、不把「Sent 查不到」当作未发送、不按 Message-ID 或内容相似度改写发送状态。用户需要再发时，复用现有会话写信入口，不把专用重试按钮设为本次必做项。

## 2. 实施顺序

### A. 先确保本地发信是可回看的会话记录

现有 `messages::list_pending_sends` 已从 SQLite 读取无远端位置、具有非取消发送任务的消息；它也能返回 `accepted`，名字不代表只能查待发。`useMessages.ts` / `ReadingPane.vue` 已有独立展示。优先复用这条链路，不为去掉 Sent 重写会话分页，也不新建一套历史表。UI 用「发信记录」而非「待发送」概括包含已发送项的区域；验收正文及收件人可回看（如已有附件则沿用本地附件访问）。

本地记录不是临时占位：成功后不得删除、不得要求补远端位置才可见。查验会话导航、摘要及排序路径是否能覆盖仅有本地发信的会话；若不能，修对应投影，不扩大普通邮件远端查询条件。远端读标记/移动等操作不得拿无远端位置的本地记录提交。服务商副本若也出现在同一会话，允许两条记录并存，但本地「发信记录」与同步邮件视觉上可区分，不伪装为两次发送，不做身份合并。

### B. 移除客户端专用归档链

1. `outbound_use_case::complete_accepted_attempt` 去掉 `enqueue_archive` 及其专用依赖，**保留带领取凭证的发送结果更新、账号版本更新及同一事务**。`send_worker.rs` 仍在提交后通知，落库错误只重试本地记录，不再次调用发送协议。
2. 移除归档 worker 启动、模块、仓储、状态实体和账号清理里的专用分支；检查调用关系后移除 APPEND 专用实现。不删公共 IMAP 登录、连接取消、文件夹发现、Sent 角色识别或通用同步规则，也不新增 Sent 特判过滤。
3. 清除归档策略的设置 UI、Port、适配器、IPC 注册及权限、DTO 和存储结构。按 V1 无历史兼容约束，清理初始化 schema，不加兼容垫片；验证使用新建开发库，不自动删除用户现有文件。Task 14 标为「退出 V1 范围」，不是「已实现」或承诺下版恢复。
4. Graph 仍使用 `sendMail`，不改为禁止服务端存副本。删除客户端专用归档策略不等于控制服务商行为；若清理 `save_to_sent_items` 参数，可省略 `saveToSentItems`、沿用 Graph 默认保存，而不是发送 `false`。

### C. 保住发信结果与刷新，不随归档清理删除

- 同一个账号 `MailOperation` 贯穿 worker 到 SMTP/Graph。取消发生在确定尚未提交时可恢复；已拿到接受证据就持久化为已发送；只在无法确认时保留未知。permit 持有到实际任务退出及本地收尾，不能提前放行账号清理。本工作区已有回执保留和分类单测，**不等于**完整 worker 链路已验收。
- 会话发信区仍依赖发送变更事件和账号版本补偿。版本不能在查询成功应用前当作已覆盖；补偿必须刷新当前会话，旧账号、旧会话或旧请求不能覆盖最新数据。保持无高频轮询。
- 原清单 F02 的 APPEND 风险随入口移除而退出 V1，不标为修复；F03 不保留副本确认链，更不能把猜测关联搬进发送状态。F01 和 F04/F05 仍按发信/会话行为验收。

## 3. 验收门槛

| 场景 | 应观察到的结果 |
| --- | --- |
| SMTP 明确受理，服务器完全不保留副本；重启应用 | 不调用 IMAP APPEND；只发过信的会话仍可打开，能回看正文、收件人及「已发送」 |
| Graph 或服务商自行保存副本 | 现有通用同步照常；本地受理结果不依赖副本，不猜测关联，也不会触发二次发送 |
| SMTP、Graph 在提交前取消 / 提交后回执丢失 / 接受后落库前取消 | 按实际 worker 链路分别证明未发起提交、未知且后续 tick 不重发、接受结果保留且账号清理等待收尾 |
| 注入本地落库失败 | 网络提交计数不增加；本地重试有界，耗尽时明确报告，不假称落库成功 |
| 会话只有发信记录，丢一次发送事件；随后切换账号或乱序返回 | 恢复焦点后补偿刷新；旧结果不写入新会话、不覆盖更新状态 |
| 从新建 SQLite 初始化，检索产品路径 | 无归档 worker、策略入口、专用 IPC 和归档表；仍可发送及同步普通邮件 |

测试建议：`cargo test --lib --offline`、`cargo test --test end_to_end_acceptance --offline`、`pnpm exec vue-tsc --noEmit`；另记录可控协议与前端竞态测试覆盖，和真实账号联调分开报告。普通用例全绿不能替代上述验收。

## 4. 自审结论

- **产品范围**：不会借「会话发信历史」重造一个 Sent 目录；服务商不代存是允许的正常情况。
- **删减边界**：删客户端归档，而非删普通同步或取消控制；不改变服务器默认保留副本的行为。
- **实施风险**：先证明本地记录可长期回看再删归档；保留条件更新、账号版本与发送结果事务，不因删归档让成功状态或已发内容消失。
- **证据边界**：本文基于已有代码及之前的审查记录拟定，未修改产品代码、未执行本设计的动态验收。
