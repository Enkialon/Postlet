# V1.0.0 前端规格

本文依据本目录的 [接口与实体规格](./ports-entities.md)、[数据模型](./data-model.md) 和 [国际化方案](./i18n.md) 编写，未核对项目代码。目录、组件与状态名称均为待实现设计，不表示已有实现。

本文定义桌面 UI 的信息架构、交互、前端职责、取数与状态流转、验收条件。接口字段和方法以 `ports-entities.md` 为准；正文可空、无 ThreadId 投影等与旧数据模型的差异遵循其 §12，不在前端补偿数据库设计。

## 1. 目标与范围

Postlet 是 Tauri 2 桌面邮件客户端，仅对接 Outlook。前端使用 Vue 3、TypeScript、Vite；国际化使用现有文档规定的编译期转换与 vue-i18n。

默认工作流是“选择联系人或群组 → 阅读往来邮件 → 管理会话”，主导航不使用收件箱、已发送、垃圾箱等文件夹树。邮件保留主题、发送者、收件人和时间信息，会话阅读不将邮件简化成缺少上下文的聊天气泡。

| V1 提供 | V1 不提供 |
|---|---|
| Outlook 账户登录、切换、退出 | 跨账户统一会话 |
| 联系人 / 群组会话列表与邮件阅读 | 写信、回复、转发、草稿编辑 |
| 通讯录查找与打开联系人会话 | 全文邮件搜索、远端联系人编辑 |
| 标记邮件已读 / 未读 | 邮件删除、归档、文件夹移动 |
| 群组创建、重命名、合并、线程迁移 | 附件下载、附件预览 |
| 同步触发、已有状态与错误展示 | 前端控制聚合任务或重试队列 |
| 账户显示配置、中文 / 英文切换 | 前端直连 Graph、持有 OAuth Token |

## 2. 信息架构与桌面布局

### 2.1 工作区

采用导航栏、列表区、阅读区三个区域。详情面板按需从阅读区侧边展开。

```text
┌──────────┬─────────────────┬──────────────────────────────┐
│ 账户切换 │ 会话 / 联系人列表 │ 会话标题、详情入口、操作菜单   │
│          │                 ├──────────────────────────────┤
│ 会话     │ 种类筛选         │ 往来邮件列表                 │
│ 联系人   │ 列表项           │ 邮件头、预览、展开正文         │
│ 群组     │ 加载更多         │                              │
│          │                 │                              │
│ 同步状态 │                 │                              │
│ 设置     │                 │                              │
└──────────┴─────────────────┴──────────────────────────────┘
```

建议初始宽度：导航栏 160px、列表区 300px、阅读区使用剩余空间；这些是设计初值，不构成平台窗口配置。宽度不足 1000px 时导航收起为带可访问名称的图标栏；不足 760px 时列表与阅读区切换展示，保留返回列表入口、选中项和滚动位置。详情面板在窄窗口覆盖阅读区，不压缩出不可阅读的正文。

各区域独立滚动；页头和错误提示保持可见。分隔线、背景和选中态建立层级，未读状态同时使用文字或图形标识，不能只靠颜色。长姓名、邮箱和主题允许截断并提供完整内容；正文允许选择和复制。

### 2.2 页面与导航状态

| 页面 | 内容 | 入口 |
|---|---|---|
| 欢迎页 | 产品说明、登录 Outlook、登录错误 | 没有已登录账户 |
| 会话页 | 全部 / 联系人 / 群组筛选、列表、阅读区 | 登录后默认页面 |
| 联系人页 | 姓名 / 地址前缀查找、联系人信息、打开会话 | 导航栏 |
| 群组页 | 根群组列表、创建入口、详情和管理操作 | 导航栏 |
| 设置页 | 当前账户、显示配置、语言、同步与退出 | 导航栏 |

导航状态至少包含 `accountId`、页面、可空 `conversationId`、可空 `messageId`。路由或等价导航管理只保存本地 ID，不放正文、邮箱、Token 和 Delta 链接。所有从导航恢复的 ID 均按当前账户重新查询，不能绕过 Rust 账户校验。

首次进入会话页不自动标记任何邮件已读；未选中会话时显示“选择联系人或群组，查看往来邮件”。空会话保持可打开，展示“还没有往来邮件”。

## 3. 页面行为

### 3.1 启动、登录与账户切换

1. 启动调用 `AccountPort.listAccounts()`；有账户时恢复仍有效的上次选择，否则使用返回列表的首项。
2. 无账户时显示欢迎页。点击登录调用 `signIn()`，等待期间阻止重复提交。
3. 登录成功后以返回的 Account 更新账户列表，进入该账户会话页，再触发邮件和联系人同步。
4. 登录失败显示可重试错误；当前 AppError 没有独立的“用户取消登录”码，不通过匹配 message 字符串猜测取消状态。
5. 切换账户时先递增前端会话版本，停止旧轮询，清除旧阅读内容和未提交表单，再加载新账户数据。迟到响应不能写回当前工作区。

退出通过 `signOut(accountId)` 完成，成功后清除该账户的前端内存缓存与导航恢复项；有其他账户则切换，否则返回欢迎页。失败保留当前视图并显示错误。当前契约未定义退出是否清除 Rust 本地历史，UI 不宣称“已删除本地邮件”，也不自行请求数据库清理。

### 3.2 会话列表

使用 `ConversationPort.listConversations()`，传入当前账户、种类、游标和分页大小。默认每页 50 项；大小为前端初值，须服从后端校验。

| 元素 | 显示规则 |
|---|---|
| 联系人标题 | 非空 `contact_display_name`，否则使用会话规范化地址 |
| 群组标题 | 非空 `group_name`，否则显示本地化“未命名群组” |
| 摘要 | `last_message_preview` 中的主题与正文预览，纯文本展示 |
| 时间 | `last_message_at`，为空不显示伪造日期 |
| 未读 | 使用后端 `unread_count`；大数量可显示 99+，可访问名称保留实际值 |
| 种类 | 联系人与群组有可区分图标和名称 |

排序遵循后端结果，前端不以已加载邮件重新计算最新消息、未读数或会话归属。接口尚未规定稳定排序的细节，见 §10。切换种类时重置游标，不把不同筛选的页面拼接。列表刷新保留仍存在的选中项；选中项未出现在当前页不代表已删除，必要时通过 `getConversation()` 核实。

V1 会话页没有全局搜索框：当前 ConversationListQuery 没有 search。联系人页的查找不得标注为“搜索所有邮件”。

### 3.3 会话阅读

选中会话后调用 `getConversation()` 和 `listMessages()`；后者以 `direction='older'` 获取最近邮件，继续加载更旧内容。邮件使用卡片展示，保留主题、发送者、时间、预览、已读状态和附件存在标识；展开后显示完整收件人与正文。

阅读区默认最近邮件在前。具体排列必须与服务端游标排序一致，不混用本地排序和服务端分页。翻页保持当前可见邮件锚点，不自动跳转到首项。读取列表只加载摘要已有字段；仅用户展开邮件时调用 `MessagePort.ensureMessageBody()`，相同账户 / 消息同时只发一个正文请求。

| 正文状态 | 呈现 |
|---|---|
| `body_content === null` | 未加载，展开时加载 |
| 请求进行中 | 卡片内加载状态，其他邮件仍可操作 |
| 返回空字符串 | 显示“此邮件正文为空”，不再次自动加载 |
| 有正文 | 按 text / html 分别渲染 |
| 请求失败 | 保留邮件头和预览，卡片内提供重试 |

正文加载完成且邮件展开后，若为未读，提交一次标记已读。只浏览会话列表、折叠卡片、加载预览和预取正文均不自动标记。用户显式标记未读后，在本次展开期间不立刻自动改回已读；再次主动展开才进入新的阅读周期。

`thread_id=null` 的邮件照常阅读与标记，隐藏线程迁移入口；不得显示“无法进入会话”的前端错误。已软删消息由后端列表排除；刷新或写入返回 not_found 时移出当前阅读结果并提示“邮件已不可用”，不凭本地缓存复活。

附件仅展示“含附件”，不伪造名称、数量或下载按钮。文件夹名称若展示，仅作为邮件详情信息。

### 3.4 联系人

联系人列表使用 `ContactPort.listContacts()`，查找输入以 250ms 防抖提交 `search`，语义为姓名 / 地址前缀。清空输入返回无筛选列表，改变输入重置游标并使旧请求失效。

联系人行显示姓名和规范化地址；没有姓名时使用地址。`graph_id=null` 的占位联系人仍可正常打开，不展示远端编辑入口。点击“查看往来”调用 `ensureContactConversation()`，使用返回的 ConversationId 导航；即便没有邮件，也保留空会话。

不在前端通过收发地址扫描邮件构建会话，不因为 ContactId 为空而拒绝打开按地址保留的历史会话。V1 不提供联系人删除或合并操作，现有前端 Port 没有这些能力。

### 3.5 群组与管理操作

群组页通过 `GroupPort.listGroups()` 获取 `include_merged=false` 的根群组；详情调用 `getGroup()`、`listParticipants()`。成员标明“往来成员”和“发信成员配置”，两种标识可同时存在。V1 无发信功能，成员配置只说明为将来发信保留的集合，不展示发送入口。

| 操作 | 交互与提交 | 成功后刷新 |
|---|---|---|
| 创建 | 输入名称、可选成员地址；`createManualGroup()` | 根群组列表与返回的群组详情 |
| 重命名 | 预填当前名称，提交 `renameGroup()` | 群组详情、会话列表标题 |
| 更新成员 | 编辑完整发信成员集合，`updateSendMembers()` | 返回成员列表及群组详情 |
| 合并 | 选同账户的另一根群组，明确“源群组并入目标群组”后确认；`mergeGroups()` | 根群组列表、目标详情、会话列表与当前阅读区 |
| 迁移线程 | 从有 ThreadId 的邮件发起，选目标根群组；提示将迁移该线程全部邮件；`moveThreadToGroup()` | 会话列表、源会话消息与群组详情 |

管理表单执行 trim、必填与邮箱格式提示，Rust 再次校验。邮箱按现有规范 trim + lowercase，去重后提交。仅展示层做输入校验，不能在前端决定群组归属、合并根解析或观测成员。

合并与迁移采用确认后提交，等待时禁用重复操作，成功前不乐观搬运邮件。失败保留表单；冲突时重新取根群组列表供用户选择。目标候选通过分页加载，不能只把当前页当作全部群组。

目前没有按 GroupId 获取或创建 Conversation 的前端方法。群组详情可独立使用；“打开群组会话”仅在已取得对应 ConversationId 时可用，不遍历全部会话页猜测映射，不因创建群组成功就假定已存在会话。补充契约见 §10。

### 3.6 设置与同步

语言设置支持 `zh-CN`、`en-US`，手动选择优先于系统语言；无手动选择且系统语言不受支持时回退中文。语言是设备偏好，不增加 AccountCommand 字段。

账户显示开关对应 `show_group_messages_in_contact_conversation`，默认关闭。调用 `AccountPort.updateDisplaySettings()`，以返回 Account 为准；提交失败恢复原值。说明文案为“在联系人会话中同时显示群组邮件”。保存成功表示配置已提交，不宣称后台重投影已完成。

同步入口分别触发邮件、联系人同步；邮件默认 `folder_ids=null`，由后端决定跟踪范围。同步详情可展示已有文件夹状态，但不提供文件夹树导航和跟踪范围编辑。

| 已知状态 | 呈现 |
|---|---|
| 邮件 idle 且从未成功 | “尚未完成首次同步” |
| 邮件 running | 不确定进度指示与“正在同步” |
| 邮件 error | “部分内容可能未更新”、上次成功时间、重试入口 |
| 邮件 idle 且有成功时间 | “上次邮件同步于……” |
| 联系人触发返回成功 | “已请求同步联系人”，随后读取成功时间 |

不生成百分比：接口没有总量。邮件同步成功也不表示聚合队列已经处理完。联系人进度 DTO 只有时间和游标，不能推断 running、失败或完成百分比。Delta / next 链接和租约不显示在产品 UI。

## 4. 前端架构与目录

```text
src/
  app/
    bootstrap.ts             # 组合根：创建 Adapter 并以 Port 注入
    navigation.ts            # 页面、账户与本地实体 ID
  ports/                     # 复用 ports-entities.md 的六个接口
  domain/                    # 生成或导出的 IPC 数据类型
  adapters/
    tauri/                   # Tauri*Adapter 与统一 IPC 错误归一化
    memory/                  # 开发及验收用内存实现
  features/
    accounts/
    conversations/
    contacts/
    groups/
    settings/
    sync/
  shared/
    ui/                      # Button、Dialog、EmptyState、ErrorState 等
    mail-content/            # 正文净化与隔离展示
    formatting/              # 时间、姓名、摘要等纯展示函数
  i18n/                      # 与 i18n.md 保持一致
```

每个 feature 可含 components、composables 和状态模块；不要求为每个按钮增加 service 或 trait。首期采用 Vue 响应式状态模块和组合函数，不把未在资料中确定的状态库、路由库或组件库设为硬依赖。

依赖方向为 `UI → feature 状态 / 组合函数 → Port 接口`。只有组合根导入具体 Adapter；feature 不创建 TauriAdapter，组件不调用 invoke。开发环境通过相同接口注入内存 Adapter，不在组件中写环境判断或假数据分支。

DTO 字段遵循 `snake_case`、枚举字符串和显式 null；Port 方法名使用 camelCase。展示 ViewModel 可有 camelCase 派生字段，但不能作为新的传输契约反向提交。GraphId、ThreadId、ConversationId 与 MessageId 不混用，所有缓存索引包含 AccountId。

Tauri Adapter 只负责调用 RS 桥、传输映射和错误归一化，不做会话聚合或待提交变更队列。具体 command 名称和参数封装尚未定稿，不在本文件虚构一套 IPC 名称。

## 5. 状态、缓存与并发

### 5.1 状态归属

| 状态 | 所有者 | 持久化 |
|---|---|---|
| 当前账户、导航、选中会话 | 应用会话状态 | 仅保存可恢复 ID，恢复时验证 |
| 会话页、联系人页、群组页数据 | 各 feature | 内存缓存，Rust 为事实来源 |
| 消息与正文 | 账户 / MessageId 缓存 | 前端不另存邮件正文 |
| 未读数、最新消息、归属 | Rust 投影 | 前端不独立重算 |
| 语言、面板宽度 | 设备偏好模块 | 本地设置，不包含邮件数据 |
| 待提交 Graph 操作、租约、generation | Rust 后台 | 不复制到前端 Store |

每类列表区分初次加载、追加加载、刷新和错误。可采用以下纯前端状态结构，不能作为 IPC DTO：

```ts
interface PageState<T> {
  items: T[];
  nextCursor: string | null;
  hasMore: boolean;
  loading: 'idle' | 'initial' | 'more' | 'refresh';
  error: AppError | null;
  requestVersion: number;
}
```

正文请求状态独立于 `body_content`，网络错误不能写成空正文；相同消息可在多个会话展示，更新实体缓存后复用数据，不能建立互相漂移的副本。

### 5.2 分页与迟到响应

列表查询键包含账户、页面类型、种类 / 搜索条件，以及消息列表的 ConversationId 和方向。每次切换条件或首屏刷新递增 requestVersion；响应只在键和版本均匹配时应用。IPC 不支持取消时丢弃迟到结果，不能误称请求已在 Rust 取消。

同一查询键同时最多一个追加请求；按本地实体 ID 去重，以新响应更新同 ID 数据。只有服务端 `has_more` 和 `next_cursor` 决定后续分页，不用返回条数猜测。`has_more=true` 却无游标时停止追加并报告契约错误，避免循环。

首屏刷新建立新分页链，旧游标全部失效；刷新后恢复仍存在的可见锚点，用户需要继续向下加载时使用新链。不得将旧分页链直接拼接到新首屏。

### 5.3 写入与刷新

标记已读采用先提交本地 Rust 用例、再刷新相关数据的方式，V1 不在前端预先累加或扣减未读数。提交期间显示操作状态；成功后刷新消息与会话列表，允许短暂保留旧未读显示并注明刷新中。失败保留旧数据。

同一消息的 markRead 串行执行，新的用户意图排在前一个操作后；刷新响应以消息操作版本校验，不能覆盖更新的用户意图。`markRead()` 成功表示本地修改与待提交操作已保存，不代表 Outlook 已确认；有 `pending_local` 时显示“等待同步”。

群组变更、配置保存和显式刷新使相关查询失效。群组名称变化影响列表标题；合并 / 迁移影响消息列表、成员和源目标会话。前端无法查询某消息的全部关联会话，故当前账户会话列表统一失效，其他会话在下次打开时重新读取。

### 5.4 后台刷新

现有 Port 无变更订阅。V1 使用不重叠的定时查询：当前账户邮件 running 时约 2 秒读取进度；窗口前台时约 15 秒刷新当前列表与选中会话，覆盖聚合滞后。窗口失焦时暂停周期读取，恢复焦点立即校验当前数据；切换账户和卸载时清理定时器。

触发邮件同步后立即读取进度，直到 idle / error；列表刷新仍独立运行，不能只在同步状态改变时刷新。联系人同步仅轮询成功时间并配合前台列表刷新，不设置一个不存在的“联系人同步中”服务端状态。查询失败保留缓存并退避到最长 60 秒；用户显式刷新可立即重试。以上间隔为初始策略，不是业务时限保证。

## 6. 正文展示边界

邮件内容是外部数据。text 正文以纯文本保留换行；主题、预览、姓名和地址均通过 Vue 文本绑定展示。html 正文经过允许列表净化后放入隔离的 sandbox iframe，不直接写入主应用 DOM。

移除脚本、事件属性、表单、内嵌 frame、对象、重定向、危险 URL 协议与能触发外部请求的样式。iframe 不授予脚本、同源、表单或顶层导航权限；内容策略默认禁止网络。净化器的具体库在实现时选定，禁止以自制正则替代 HTML 解析净化。

V1 默认不加载远程图片；CID 附件资源没有下载接口，展示替代文本，不构造不存在的本地资源地址。外链须经过协议校验，只允许 http / https，经独立平台能力适配器交给系统浏览器；iframe 内点击不直接导航应用。平台能力不复用邮件业务 Port，也不能让 feature 导入 Tauri 实现。mailto 不触发 V1 不支持的写信流程。

邮件正文容器与动态邮件数据不参与自动国际化。完整内容不能写入日志或设备偏好存储。

## 7. 错误、空态与可访问性

| 情况 | UI 行为 |
|---|---|
| 首次列表请求失败 | 区域内错误与重试，不伪装成空列表 |
| 追加失败 | 保留已有项目，在列表末尾重试 |
| 后台刷新失败 | 保留已加载内容，显示“内容可能未更新” |
| 网络不可用 | 已加载或 Rust 本地可读内容继续使用；未缓存正文提示无法加载 |
| auth | 提示重新登录，保留当前上下文；不自动无限拉起登录 |
| validation | 表单或操作就地提示，不做自动重试 |
| conflict | 刷新对象与候选目标，由用户重新确认 |
| not_found | 移除失效选择或卡片，保留可用列表 |
| internal / 未识别异常 | 显示通用本地化错误，允许显式重试 |

前端使用 `AppError.code` 和操作上下文选择文案，`retryable` 控制重试入口；不解析 message 推导业务类型。后端脱敏 message 只作为可选详情，不直接当翻译 Key。

空态分别覆盖：无账户、尚无会话、没有联系人、没有群组、前缀查找无结果、空会话、已加载空正文。同步进行中的空列表可同时显示“邮件正在同步，会话稍后更新”，不宣称邮箱为空。

键盘支持 Tab 访问区域与操作，Enter 打开列表项，Esc 关闭菜单 / 对话框。对话框限制焦点并在关闭后恢复触发点；合并与迁移确认清晰标明源、目标及影响范围。图标按钮有本地化可访问名称，加载与错误通过适当 live region 宣告。200% 缩放时操作仍可到达，不强制单行溢出。

## 8. 国际化与展示格式

遵循 [i18n.md](./i18n.md)：组件模板直接写静态中文，编译期提取转换；动态数量、错误状态、日期和数字使用统一格式化 / 显式国际化辅助函数。缺少翻译回退中文，切换语言无需重启。

不翻译邮件主题、正文、附件信息、联系人姓名和用户群组名称。时间戳按本地时区显示，完整时间可查看；缺失时间展示“时间未知”，不以当前时间替代。后端 SyncStatus 和错误码映射为 UI 文案，不直接显示英文枚举。

开发验收分别执行独立的 extract、人工译文补全、check 与构建验证。普通构建不得覆盖语言资源，禁止运行时扫描整个 DOM 翻译。

## 9. 开发顺序与验收

按业务闭环推进，每步都通过 Port 接入；不要求先实现所有组件和状态模块。

| 阶段 | 可交付界面 | 关键验收 |
|---|---|---|
| 1 | 壳布局、DI、内存 Adapter、基础 i18n | 无账户 / 空列表 / 错误态可预览，feature 不绑定具体实现 |
| 2 | 登录、账户切换、会话与正文阅读 | 账户 A 慢响应不能进入 B；null 正文仅按需加载，空串不重复获取 |
| 3 | 联系人查找、打开会话、已读操作 | 前缀变更重置分页；同一消息跨会话状态一致；无 ThreadId 可阅读 |
| 4 | 群组详情、创建、改名、合并、迁移 | 明确操作范围；失败保留表单；成功读取 Rust 投影，空群组可使用 |
| 5 | 同步刷新、配置、恢复与内容隔离 | 旧游标不复用；同步失败保留内容；恶意 HTML 无脚本及网络执行 |

必要验证使用内存 Port 和可控延迟 / 失败响应，测试实际边界：账户切换、搜索乱序、分页刷新、连续已读意图、群组冲突、后台失败恢复。组件交互验证覆盖键盘、焦点与缩放；正文验证覆盖脚本、事件属性、外链、远程资源与空正文；国际化测试遵循独立规格。

联调时验证 IPC 的 snake_case、枚举、null、时间戳及错误归一化。测试不得只检查组件是否调用某个函数，还须检查最终展示、缓存账户隔离和用户能否继续操作。

## 10. 契约缺口与实现前约定

以下是本目录资料尚未完整规定的边界，不视为已存在接口；涉及后端补充时应先更新 `ports-entities.md`。

| 边界 | V1 当前处理 | 后续需明确 |
|---|---|---|
| 会话 / 消息稳定排序 | 保持后端分页顺序，不自行混排 | 时间取值优先级、同时间 ID 次序、空时间位置、游标对变更的语义 |
| 群组打开会话 | 只在已有 ConversationId 时导航；其余保留独立详情 | 按 GroupId 获取 / 确保群组会话的能力 |
| 群组全部线程 | 从当前邮件 ThreadId 发起迁移 | 如需线程管理页，补充线程分页查询 |
| 联系人同步进度 | 只展示触发结果和最近成功时间 | running / error、取消及完成通知 |
| 聚合完成与配置重建 | 周期刷新投影，不宣称立即完成 | 聚合进度、重投影状态及通知 |
| 后台事件 | 使用现有 Port 轮询 | 若引入订阅，先规定事件账户、版本、退订与遗漏补偿 |
| 退出行为 | 清前端缓存，不承诺清数据库 | 登录态撤销、本地保留与清除策略 |
| 本地待提交错误 | 展示 pending_local，不提供无依据的重试面板 | 字段级失败查询与手动重试入口 |
| command 映射 | Adapter 保留实现位置 | command 名、参数包裹、错误序列化与登录取消结果 |

全文搜索、未读专用筛选、联系人编辑、附件和写信应按后续版本需求扩展端口，不能通过前端扫描已加载页来冒充完整能力。
