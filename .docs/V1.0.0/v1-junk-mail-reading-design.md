# V1 设计：普通邮件正常渲染，垃圾邮件只显示文本

状态：待实施。本文只定义阅读行为与垃圾邮件操作，不改变会话优先导航。

## 产品规则

只有两种阅读行为，以邮件当前位置是否属于垃圾邮件文件夹为准，不另设「图片授权」或「追踪邮件」状态。

| 邮件位置 | 正文 | 阅读页右上角 |
| --- | --- | --- |
| 普通文件夹 | HTML 邮件直接在现有安全隔离中渲染并加载允许的图片；纯文本原样显示。不出现远程图片提示或授权按钮。 | 菜单提供「标为垃圾邮件」 |
| 垃圾邮件文件夹 | 有纯文本就显示纯文本，否则把 HTML 源码当作文字显示。不创建正文 iframe，不激活正文链接，不加载远程资源。 | 提供「移出垃圾邮件」 |

「标为垃圾邮件」只移动当前邮件，不拉黑发件人、不影响后续来信。不自动识别追踪、不自建垃圾邮件分类。普通邮件自动加载外链图片时，请求仍可能被图片服务商记录，这是本方案接受的取舍。

## 文件夹设置与会话列表

- 在现有账号文件夹列表的每行提供「设置」弹窗。首期只新增垃圾邮件角色设置：**自动识别 / 是垃圾文件夹 / 不是垃圾文件夹**。自动识别使用现有协议角色识别（如 IMAP `\Junk`、Graph 已知垃圾邮件文件夹），不另写名称猜测。用户显式选择优先于自动结果；「不是」也要持久化，不能在下一次发现文件夹时被自动规则覆盖。切回「自动识别」才撤销手动选择。
- 用邮件当前远端位置所属文件夹的**生效角色**判定，不给每封邮件另存一套垃圾标记。角色改动对已有本地邮件与后续同步的邮件都生效，无须重拉正文；刷新受影响的列表和打开中的正文。同步开关仍决定是否拉取，不因标为垃圾而自动关闭。
- **默认会话列表仍查出已同步的垃圾邮件**，包括全部由垃圾邮件组成的会话；同一会话可混合普通邮件和垃圾邮件，逐封标注、逐封决定怎样渲染。列表显示普通文本摘要和「垃圾邮件」标记，不加载正文资源。不另建垃圾箱主导航。
- 弹窗是后续文件夹配置的入口；拉取频率、监听不在本次实现，不提前设计通用表单或调度框架。

## 实现边界

- **正文展示**：复用现有文件夹角色 `junk`，由阅读页传入正文组件（`src/shared/mail-content/MailBodyView.vue`），不要靠文件夹显示名猜测。删除逐封 `allowRemoteImages` 状态和横幅。普通 HTML 继续使用隔离 iframe、现有净化规则、CSP 与 URL 校验；不允许邮件脚本、表单或直接导航。垃圾邮件正文用文本插值输出，不用 `v-html`。如果现有正文模型只保留 HTML，直接显示源码即可，不为这项功能加存储结构。
- **标记与移出**：通过现有 Port/Adapter、位置校验和远端移动机制实现。标记时优先移入同账号仍生效的服务端标准垃圾邮件文件夹；若它已被手动取消，则仅在存在唯一生效的垃圾文件夹时选它，否则提示配置，不猜目标。移出时移入同账号已确认且未标为垃圾的收件箱，不额外保存「原文件夹」。目标未配置或记录没有远端位置时，不执行移动，不假装操作成功。只移动当前邮件，不把整个会话一起移走。
- **以移动结果为准**：从发起「标为垃圾邮件」起即可暂停该正文的 HTML 渲染；失败后恢复原状态并显示错误。「移出垃圾邮件」在后台排队、等待确认或失败时仍只显示文本，确认移出后才能正常渲染。复用移动的「旧位置移除、新位置新增」规则；若新位置尚未同步，刷新会话，不按 Message-ID 自动重绑详情，也不提前解锁旧正文。
- **不做额外入口**：不新增垃圾箱主导航、图片偏好设置或白名单，不与文件夹级同步、监听功能捆绑实施。

## 验收

1. 打开普通 HTML 邮件，允许的图片直接显示，没有授权横幅；原有 HTML 隔离与链接安全规则仍有效。
2. 打开垃圾邮件，有纯文本就显示文本，只有 HTML 时显示可读的字面源码；验证不创建正文 iframe、没有远程资源请求。普通邮件切到垃圾邮件时也不能误用上一封的渲染状态。
3. 对 IMAP 和 Graph 分别验证标记与移出只影响当前邮件。移出成功后恢复普通渲染；远端失败、仅入队或目标缺失时不提前渲染。
4. 默认会话列表能找到仅含垃圾邮件的会话；同会话混有普通邮件和垃圾邮件时，每封的标注与渲染规则独立；本机发信记录等无远端位置项不会触发移动。
5. 自动识别的垃圾文件夹可手动取消，普通文件夹可手动标为垃圾；重新发现文件夹后覆盖仍生效，切回「自动识别」恢复协议默认。验证已有邮件和新同步邮件使用同一规则，同时不改变同步开关。
